# London Walk/Drive — an OpenStreetMap proof of concept

A small browser demo answering the question: *can you build a game where you
walk or drive through an accurate representation of London using only publicly
available map data?*

It renders ~1.4 km² of Westminster — Trafalgar Square, Whitehall, Big Ben,
Westminster Abbey, St James's Park, the Thames and the London Eye — as a 3D
world you can walk or drive around in first person. All geometry comes from
[OpenStreetMap](https://www.openstreetmap.org): real building footprints
(with tagged heights where mappers have surveyed them), the real street
network, parks and the river. No game assets, no hand-modelling.

## Run it

```sh
cd london-demo
python3 -m http.server 8000
# open http://localhost:8000/
```

On first load the page fetches live data from the Overpass API (a public
OpenStreetMap query service) — usually a few MB, a few seconds. It is cached
in localStorage when it fits. If you're offline or want instant loads,
pre-bake the data once:

```sh
python3 fetch_data.py     # writes data/london.json; the page prefers it
```

### Controls

| Key | Action |
| --- | --- |
| Mouse | look around |
| W A S D | move (walk) / throttle & steer (drive) |
| Shift | sprint on foot |
| C | toggle walk ↔ drive |
| R | respawn at Parliament Square |
| Esc | release the mouse |

### URL parameters

- `?bbox=south,west,north,east` — load a different area (any city with OSM
  coverage works, not just London; keep it under ~2 km on a side or the
  download gets large).
- `?data=path.json` — load a raw Overpass JSON response from a file
  (`?data=test/fixture.json` loads a tiny synthetic scene used by the smoke
  test).
- `?autostart` — skip the click-to-start overlay (used by the smoke test).

## How it works

1. One Overpass query fetches buildings (ways *and* multipolygon relations),
   highways, parks/green space and water for the bounding box, with geometry
   clipped to the box.
2. Coordinates are projected to a local metres-east/metres-north plane
   centred on the box.
3. Buildings become extruded `THREE.Shape`s. Height priority: `height` tag →
   `building:levels` × 3.1 m → a deterministic 9–18 m default. Courtyards
   (multipolygon inner rings) become holes. Everything merges into a single
   vertex-coloured mesh, so the whole city is a handful of draw calls.
4. Roads become flat ribbons with widths/colours by highway class; footways
   and pedestrian areas sit slightly higher than carriageways.
5. Water and green polygons that Overpass clipped at the bbox edge (e.g. the
   Thames) arrive as open chains; they are re-closed by stitching chains and
   walking along the bbox border, trying both directions and keeping the
   smaller-area result.
6. A pointer-lock first-person controller does walking; drive mode is a
   simple arcade model (throttle/drag, speed-scaled steering, mouse-look
   that re-centres as you move).

## Known limitations (it's a proof of concept)

- No collision — you can walk through walls and drive through the Abbey.
- The world is flat: no terrain elevation, and bridges sit at water level
  rather than arching over the river.
- No textures or building parts — Big Ben is an accurate 96 m box, not a
  clock tower. Facade detail is where you'd graduate to `building:part`
  tags, procedural facades, or a photogrammetric tile source.
- Overpass relation handling covers the common cases (outer/inner rings,
  split ways) but not every exotic multipolygon.

## Where you'd take it next

- **Terrain & bridges**: Environment Agency LIDAR (1 m, Open Government
  Licence) for real ground heights; `layer`/`bridge` tags for decks.
- **Collision**: a 2D spatial hash of building footprints is enough for
  walk mode.
- **Visuals**: procedural facade textures keyed off `building:levels`,
  street furniture from OSM nodes (trees, lamps), or swap the whole ground
  truth for Google Photorealistic 3D Tiles via Cesium if the budget allows.
- **Scale**: tile the Overpass queries and stream chunks in and out as the
  player moves to cover more than one neighbourhood.

## Smoke test

`test/fixture.json` (generated by `test/make_fixture.mjs`) is a synthetic
scene exercising the parser: building ways, a multipolygon with a courtyard,
tagged heights, roads, a park, a pond and a clipped water body. Load it with
`?data=test/fixture.json&autostart` and check `window.__demo.counts`.
